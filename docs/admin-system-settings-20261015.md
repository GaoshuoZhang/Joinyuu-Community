# 系统配置整合与通知渠道简化

日期：2026-10-15。按本次五项需求实施，继续使用 TDesign Vue Next。

## 页面结构

系统管理菜单保留统一「系统配置」入口，移除原来的移动端主题、归档管理、消息中心独立菜单。系统配置使用以下选项卡：

| 主选项卡 | 内部栏目 |
| --- | --- |
| 基础设置 | 站点信息、功能开关、名片字段、运营参数、实名核验、对象存储、许可证 |
| 移动端主题 | 当前主题、主题包上传与管理 |
| 通知渠道配置 | 渠道配置、模板配置、发送记录 |
| 归档管理 | 各业务域归档列表与归档设置 |

原消息中心标题与前端权限目录显示名称改为「通知渠道配置」，权限码仍为 `/system/messages`。种子数据定义同步改名，但未执行种子脚本或修改现有权限数据库。

新聚合页根据原权限过滤主选项卡：拥有通知或归档权限的账号无需额外取得基础设置权限；无权限面板不挂载、不发起对应请求。

## 固定通知配置

- 短信、邮箱和站内信各显示一个固定设置卡片，提供「配置短信 / 配置邮箱 / 配置站内信」入口。
- 移除新增渠道、渠道名称、消息类型等管理多个渠道时才需要的操作；首次配置仍通过同一个设置入口保存。
- 短信基本表单仅展示供应商、启用状态、签名、供应商必要参数、凭据和模板对应关系。
- 模板对应关系改为字段行，提供默认通知编码 `verify_code`；半填行、重复编码和空映射在字段旁报错。
- 地区、端点、凭据来源、每日发送上限与备注放入高级设置；SMTP 的 TLS 使用 TDesign Switch。
- 保存通过 `PUT /api/admin/message-channels/fixed/:kind` 完成。同一通知类型使用事务与 PostgreSQL 事务级锁串行保存，首次配置、供应商切换和停用其他历史配置一起提交。
- 历史配置与发送记录的关联保留；下一次保存该类型的固定配置时，其他候选配置自动停用，不执行历史数据删除。
- 仅同一供应商、相同凭据模式可沿用旧凭据。切换供应商或凭据模式不混用密钥；空密钥仍不回显。
- 旧新增接口遇到该通知类型已有记录时拒绝再新增。UI 的保存与供应商切换统一使用固定配置接口。

## 路由与草稿

旧地址继续兼容：

| 旧地址 | 新地址 |
| --- | --- |
| `/system/mobile-themes` | `/system/config?tab=themes` |
| `/system/trash` | `/system/config?tab=archive` |
| `/system/messages` | `/system/config?tab=notifications` |
| `/system/messages?tab=outbox&page=3&status=failed` | `/system/config?tab=notifications&messageTab=outbox&outboxpage=3&outboxstatus=failed` |

归档筛选使用 `archive` 参数前缀，发送记录使用 `outbox` 前缀，防止聚合后筛选互相覆盖。主选项卡使用 `tab`，基础设置栏目使用 `section`，通知内部栏目使用 `messageTab`。

基础设置切换栏目或主选项卡时保留草稿，离开页面仍有未保存保护。保存会校验全部基础设置；隐藏栏目有错误时先切换栏目，再聚焦错误字段。许可证管理不受基础表单的禁用状态影响。
