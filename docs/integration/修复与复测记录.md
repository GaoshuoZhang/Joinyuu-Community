## 7. 内置 V1.0 协议（正式部署兜底）

### 问题

正式部署通常只执行迁移、不导入开发种子，数据库中没有已发布的用户协议/隐私政策（Policy 表 `agreement_user` / `agreement_privacy`）：

- `POST /api/app/auth/register` 返回 `400 用户协议或隐私政策尚未发布`，注册页仅弹出该提示，无法创建账号；
- `GET /api/app/policies/:kind` 返回 404，协议页无法展示版本内容。

另：`apps/api/prisma/migrations/20260920180000_default_agreements` 目录为空（无 `migration.sql`），会使 `prisma migrate deploy` 直接失败（P3015），已删除。

### 方案

| 层 | 内容 |
|---|---|
| 内置内容 | 新增 `apps/api/src/common` 之外的 `modules/app/policies/builtin-agreements.ts`：用户协议与隐私政策 V1.0（版本 `1.0`、生效日 2026-01-01，分八节完整条款） |
| 接口兜底 | `GET /api/app/policies/:kind` 按最新 published 优先；缺失时返回内置 V1.0，并带 `builtIn: true`；未知 kind 仍 404 |
| 注册兜底 | 注册时协议版本解析 DB published 优先、缺失回退内置 V1.0，不再抛 400；`AgreementConsent.version` 记为 `1.0` |
| 迁移自带 | 新增迁移 `20260920180000_builtin_agreement_v1`：仅当某协议不存在 published 行时写入内置 V1.0（`ON CONFLICT DO NOTHING`，不覆盖后台已发布内容） |

### 验证

- **全新库**：新建空库仅执行 `prisma migrate deploy`（不跑种子）→ `Policy` 表自动出现 `PL1001/PL1002`（published / 1.0）。
- **接口与注册**：新增 `apps/api/test/builtin-agreements.e2e-spec.ts` 3 例通过（未发布时回退内置 V1.0 + `builtIn:true`；未发布时注册成功且同意留痕版本为 1.0；有已发布版本时优先数据库且 `builtIn:false`）；API 全量 e2e **44 套 / 298 例全部通过**。
- **部署环境实测**：对部署库（`joinyuu`，此前未应用任何新迁移、无协议数据）执行 `prisma migrate deploy` 后，在移动端真实注册新账号成功（跳转首页），`AgreementConsent` 两条均为 `1.0`，`/privacy` 正常展示 V1.0 协议全文；验证账号已清理。证据：`evidence/retest3-register-builtin-agreement.png`、`evidence/retest3-privacy-builtin-v1.png`。
- 三端 lint / build、移动端 71 例单测均通过。

### 部署步骤

1. 发布新代码后执行数据库迁移：`pnpm --filter @joinyuu/api db:migrate`（即 `prisma migrate deploy`，会自动写入内置 V1.0 协议）；
2. 重启 API 即可注册（无需导入种子）；
3. 后续如需替换正式协议，在后台政策管理发布新版本后，接口自动优先数据库版本（`builtIn=false`）。
