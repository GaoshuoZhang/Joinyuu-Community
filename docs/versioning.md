# 多仓版本与产品发布

API、后台、移动 Web、小程序各自使用本仓 package.json 的 version，独立维护语义化版本与 CHANGELOG，不再锁步改号。迁移本身保留原软件版本。

协作仓的 package.json 版本是工作区工具版本，不代表四端必须同号。每次产品发布在 releases/ 记录四仓固定 commit SHA、软件版本和 tag，并补充接口契约版本、所需数据库迁移、验证结果、部署顺序与回退要求。

```sh
pnpm workspace:status
pnpm release:record product-2026-10-29
```

生成器要求各业务仓工作树干净，拒绝覆盖已存在的同名清单。生成清单不代表已经部署。只有经过联调并注明验证与发布状态的组合，才作为产品部署依据。

通常先发布向后兼容的 API，再发布消费者；接口删除与语义变更采用分阶段迁移，并保留对已发布小程序版本的兼容。升级前备份数据库与支付加密主密钥，代码回退不能替代数据库回退。
