## 1. 先看全貌：我们要搭出什么

最终形态：**两个网页（管理后台 + 手机端）、一个后端服务、两个数据库/中间件**，通过 Nginx 串在一起：

```
                        ┌─────────────────────────── 服务器（一台 Linux） ──────────────────────────────┐
浏览器/手机               │                                                                              │
  │                      │  ① 1Panel 的 Nginx（OpenResty）                                               │
  │  访问 admin.你的域名  │      ├─ 静态网站 A：管理后台  apps/admin/dist                                  │
  ├──────────────────────┼──────┤   └─ 反向代理 /api  ─┐                                                   │
  │  访问 m.你的域名      │      ├─ 静态网站 B：移动端    apps/client-mobile/dist                          │
  └──────────────────────┼──────┤   └─ 反向代理 /api  ─┤                                                   │
                         │      └──────────────────────┼────────────────────────┐                         │
                         │                             ↓                        │                         │
                         │              ② 后端 API  NestJS  127.0.0.1:7757     │  （只有这台机器能访问）     │
                         │                             ↓                        │                         │
                         │              ③ PostgreSQL 5432   ④ Redis 6379   ⑤ MinIO 9000（可选）           │
                         └──────────────────────────────────────────────────────────────────────────────┘
```

关键点（记住这 5 句话就够）：

1. **后端只监听本机 7757 端口**，外面访问不到，只能由 Nginx 转发进来——这样最安全。
2. **管理端和移动端都是「静态网页」**，由 Nginx 直接发文件，不需要 Node 去跑它们。
3. **两个页面都通过 `/api` 找后端**，所以每个网站里都要加一条 `/api` 反向代理。
4. **移动端必须放在一个域名的最顶层**（例如 `m.你的域名`），不能放在 `你的域名/app/` 这种子目录下。
5. **1Panel「运行环境」里的后端其实跑在容器内**：容器里的 `127.0.0.1` 指的是**容器自己**，不是服务器。所以用面板托管后端时，`.env` 里数据库/Redis 的地址必须改成容器能访问到的名字（详见[第 9 步方案 A](#11-第-9-步让后端常驻运行)）——这是本手册最容易踩的一个坑。

## 3. 第 1 步：安装 1Panel

**在哪里做**：服务器的 SSH 终端（云的「远程登录」窗口即可）。

1. 用 `root` 用户登录服务器，执行官方一键脚本：

```bash
bash -c "$(curl -sSL https://resource.fit2cloud.com/1panel/package/v2/quick_start.sh)"
```

2. 安装脚本会问你面板端口、安全入口、用户名、密码。**建议全部按它的默认值走，直接把最后打印出来的这一块抄下来保存**：

```
面板地址: http://123.45.67.89:xxxxx/xxxxxx
面板用户: xxxxxx
面板密码: xxxxxx
```

3. 浏览器打开上面那个「面板地址」→ 输入账号密码 → 进入 1Panel。

**看到什么算成功**：能看到 1Panel 的「概览」页面，顶部有 CPU、内存、磁盘等图表。

> 忘记面板地址/密码时：在服务器终端执行 `1pctl user-info` 可以重新查看。

**顺手做一件事**：左侧菜单找到「系统 → 文件」或「主机 → 终端」（不同版本位置略有差异，找不到就用菜单上方的搜索框搜「终端」），确认你能打开网页版终端——后面很多命令在这里执行很方便。

## 4. 第 2 步：安装 PostgreSQL 与 Redis（必须）

**在哪里做**：1Panel 左侧菜单「应用商店」。

### 4.1 安装 PostgreSQL（数据库，必装）

1. 应用商店 → 搜索框中输入 `PostgreSQL` → 点「安装」。
2. 在弹出的安装表单里填写：

| 字段 | 填什么 |
| --- | --- |
| 名称 | `postgresql`（默认即可） |
| 版本 | 选默认的 17 版本（与项目一致） |
| 端口 | `5432`（默认；若被占用改成 55432，后面 `.env` 也要跟着改） |
| 用户名 | `joinyuu`（建议与项目默认一致） |
| 密码 | **自己设一个强密码**（记到第 2 步的表格里） |
| 数据库 | `joinyuu` |
| 允许远程连接 | **不要勾**（后端就在本机，不需要远程连） |

3. 点「确认」，等待状态变成「已启动」（绿色）。

### 4.2 安装 Redis（缓存与会话，必装）

1. 应用商店 → 搜索 `Redis` → 点「安装」。
2. 表单里填：

| 字段 | 填什么 |
| --- | --- |
| 名称 | `redis`（默认） |
| 端口 | `6379` |
| 密码 | **自己设一个强密码**（记到表格里） |
| 持久化 | 保持默认开启 |

3. 确认安装，等待状态变成「已启动」。

### 4.3 安装 MinIO（对象存储，可选但推荐）

**什么情况下需要**：网站上会有图片、合同、素材等文件。项目默认把文件存到服务器磁盘（够用、最简单）；若希望文件独立存放/便于扩容/多台服务器共享，就用 MinIO。

1. 应用商店 → 搜索 `MinIO` → 安装。
2. 表单里填：

| 字段 | 填什么 |
| --- | --- |
| 名称 | `minio` |
| 端口 | `9000`（API）、`9001`（控制台） |
| 用户名（AccessKey） | 自己设（记下来） |
| 密码（SecretKey） | **强密码**（记下来） |
| 存储路径 | 默认 |

3. 安装完成后，**不要**在云安全组/防火墙对外放行 9000/9001——只让服务器自己访问即可。

> 若暂时不确定要不要 MinIO：**先不装**，用默认磁盘存储也能正常上线；以后想切换，在管理后台「系统配置 → 对象存储」里打开并填 Endpoint 即可（见第 14 步）。

## 5. 第 3 步：放行端口、设置防火墙

**在哪里做**：两个地方都要设：① 云厂商控制台的「安全组」；② 1Panel 左侧「系统 → 防火墙」。

**要放行的端口**：

| 端口 | 用途 | 是否对外放行 |
| --- | --- | --- |
| `80` | HTTP（申请证书、自动跳转到 HTTPS 用） | ✅ 放行 |
| `443` | HTTPS（正式访问） | ✅ 放行 |
| 面板端口（形如 `xxxxx`） | 登录 1Panel 面板 | ✅ 放行（也可只放行你自己的办公 IP，更安全） |
| `7757` | 后端 API | ❌ **不要放行**（只给本机 Nginx 用） |
| `5432` | PostgreSQL | ❌ 不要放行 |
| `6379` | Redis | ❌ 不要放行 |
| `9000` / `9001` | MinIO | ❌ 不要放行（需要时用 SSH 隧道临时看控制台） |

**操作**：1Panel →「系统 → 防火墙」→「端口规则」→「添加规则」，把 80、443（以及面板端口）加进去；同时到云厂商控制台的安全组里做同样的事（两处都放行才通）。

> ⚠️ **如果用面板「运行环境」托管后端**：创建运行环境时，端口行的「**端口外部访问**」开关**实测默认是开启的**（= 绑定 `0.0.0.0`，对全网开放）。请在[第 9 步方案 A](#11-第-9-步让后端常驻运行)里把它**关掉**（或按 1Panel v2.3+ 的「容器端口」防火墙规则单独限制）——否则 7757 会直接暴露到公网。

## 6. 第 4 步：把代码放到服务器上

**要放哪里**：建议统一放在 `/opt/joinyuu`（干净、好找、不占系统目录）。

**方式一（推荐）：用 Git 拉取**

在 1Panel 的终端里执行（逐行输入，每行回车）：

```bash
# 1) 创建目录并进入
mkdir -p /opt && cd /opt

# 2) 拉取代码（公开仓库可直接拉；私有仓库需要先在 GitHub 配置访问令牌或用 SSH key）
git clone https://github.com/GaoshuoZhang/Joinyuu-Community.git joinyuu

# 3) 进入项目目录
cd /opt/joinyuu

# 4) 记录当前版本号，升级/回滚时要对照
git rev-parse HEAD
```

**方式二：上传压缩包**

1. 在你自己电脑上把项目打包成 zip（**打包前删掉 `node_modules`、`.git` 可以更小**）。
2. 1Panel →「系统 → 文件」→ 进入 `/opt` → 点「上传」选文件 → 上传完成后右键压缩包 →「解压」。
3. 解压后确认目录结构是 `/opt/joinyuu/apps/api/...`（若解压出来多了一层，把里面的目录整体移到 `/opt/joinyuu`）。

**看到什么算成功**：终端里执行下面的命令，能看到 `apps`、`docs`、`package.json` 三样东西：

```bash
cd /opt/joinyuu && ls -l
```

> ⚠️ 如果服务器上没有 `git`，先装一下：
> Ubuntu/Debian：`apt update && apt install -y git`
> CentOS/RHEL：`yum install -y git`

## 7. 第 5 步：安装 Node.js 与 pnpm

本项目后端需要 **Node.js 20 或更高版本**（NestJS 11 的要求），包管理器用 `pnpm`。

**推荐做法（在终端里装，最省事）**：

```bash
# 1) 装 Node.js 22 LTS（用 NodeSource 官方源）
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs

# 2) 检查版本：应显示 v22.x
node -v

# 3) 启用 pnpm（Corepack 自带，无需额外下载）
corepack enable
pnpm -v
# 若上一步报错，改用手动安装：npm i -g pnpm

# 4) 确认版本符合要求
node -v   # 需要 >= v20
pnpm -v   # 需要 >= 9
```

**如果是用 1Panel「运行环境」托管后端（第 9 步方案 A）**：后端运行所需的 Node 由面板的容器提供，这里**只需要能用 `pnpm` 装依赖和构建**即可。用上面第 1、3 步装一个系统 Node + 启用 pnpm 就够了（系统 Node 只用来跑 pnpm/build，不负责跑后端）。

> 关键约定：**依赖始终在服务器上用 pnpm 安装**（第 9 步），面板运行环境里的「安装 node_modules」要**保持关闭**——两边都装会互相打架。

## 8. 第 6 步：写后端配置文件 apps/api/.env

后端的全部配置都在这一个文件里。触摸不到就照抄模板。

**在哪里做**：1Panel →「系统 → 文件」→ 进入 `/opt/joinyuu/apps/api` → 找到 `.env.example`，**复制一份改名为 `.env`**（右键 → 复制 → 粘贴 → 重命名），然后双击 `.env` 打开编辑。

**照下面填写（★ 为必填）**：

```ini
# ---------- ★ 必填 ----------
# 固定写 production：只有它才会关闭「把短信/邮箱验证码回显到接口」等调试行为
NODE_ENV="production"

# PostgreSQL 连接串。把 用户名/密码 换成第 4 步设置的值；库名 joinyuu 一般不用改。
# ⚠️ 主机地址取决于后端怎么跑：跑在服务器上（第 9 步方案 B/C）就用 127.0.0.1；
#    跑在面板「运行环境」里（其实是容器，第 9 步方案 A）它指的是容器自己，必须改成容器可达地址。
DATABASE_URL="postgresql://joinyuu:你设的数据库密码@127.0.0.1:5432/joinyuu?schema=public"
# 容器方案改成下面这行（postgresql 换成 1Panel「容器」列表里数据库容器的名称）：
# DATABASE_URL="postgresql://joinyuu:你设的数据库密码@postgresql:5432/joinyuu?schema=public"

# Redis 连接串。注意密码前面有一个冒号，写成 redis://:密码@主机:6379/0
REDIS_URL="redis://:你设的Redis密码@127.0.0.1:6379/0"
# 容器方案改成下面这行（redis 换成 Redis 容器的名称）：
# REDIS_URL="redis://:你设的Redis密码@redis:6379/0"

# 后端签发登录凭证用的密钥。必须自己生成一串随机值，命令见下方
JWT_SECRET="把下面命令生成的字符串粘贴到这里"

# ---------- 服务与网络 ----------
PORT=7757
TZ="Asia/Shanghai"
# 走 Nginx 反向代理时保持 1（让审计日志与限流能拿到访客真实 IP）
TRUST_PROXY=1

# ---------- 文件存储 ----------
# 默认存在 apps/api/uploads；建议改到独立目录，升级/重装时不会丢
UPLOAD_DIR="/data/joinyuu/uploads"

# 只有在第 4.3 步装了 MinIO 时才填（否则保持注释）
# MINIO_ACCESS_KEY="你在 MinIO 里设的用户名"
# MINIO_SECRET_KEY="你在 MinIO 里设的密码"
```

**生成 JWT_SECRET**：在终端执行下面这条，把输出的那串字符整行复制到上面：

```bash
openssl rand -hex 32
```

**四个容易写错的地方（务必自查）**：

| 容易错 | 正确写法 |
| --- | --- |
| **用面板运行环境（容器）托管后端，却仍写 `@127.0.0.1`** | 改成容器名（如 `@postgresql`）或 `@host.docker.internal`，详见[第 9 步方案 A](#11-第-9-步让后端常驻运行) 第 5 点 |
| Redis 密码前漏掉冒号 | `redis://:密码@127.0.0.1:6379/0` |
| 密码里有 `@` `:` `/` 等符号没转义 | 密码只使用字母+数字，最省事 |
| `NODE_ENV` 写成 `development` 或没写 | 必须 `production`（否则验证码会被直接回显给接口，存在安全风险） |

**关于 CORS**：**不需要配置**。因为管理端、移动端和后端在同一个域名下（Nginx 转发 `/api`），浏览器同源，跨域规则不生效。`CORS_ORIGINS` 保持注释即可。

**看到什么算成功**：`.env` 文件里 4 个必填项都不是占位符（没有 `CHANGE_ME`、没有「你设的…」这类中文）。

## 9. 第 7 步：安装依赖并构建后端

**在哪里做**：1Panel 终端。

```bash
# 1) 进入项目根目录
cd /opt/joinyuu

# 2) 安装全部依赖（第一次会比较慢，几分钟；会自动生成数据库访问代码）
pnpm install

# 3) 构建后端（产物在 apps/api/dist）
pnpm build:api
```

**看到什么算成功**：第 3 步执行完，没有任何红色 `Error`，且执行下面命令能看到 `main.js`：

```bash
ls -l /opt/joinyuu/apps/api/dist/main.js
```

**如果构建到一半被系统杀掉（内存不足）**：临时加交换分区再重试：

```bash
# 临时加 2G 交换文件
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile

# 重新构建
cd /opt/joinyuu && pnpm build:api
```

## 10. 第 8 步：初始化数据库

这一步把数据表建出来，并写入**基础配置**（字典、权限、角色、一个超级管理员账号等）。**不会写入任何演示数据。**

**在哪里做**：1Panel 终端，在项目根目录执行：

```bash
cd /opt/joinyuu

# 1) 建表（应用所有数据库迁移）
pnpm db:migrate

# 2) 写入基础配置（只会执行一次；已初始化的库会被自动拒绝）
pnpm db:init
```

**默认会随机生成一个超级管理员密码并打印在屏幕上，只打印这一次**，请立刻抄下来：

```
[init] 超级管理员：admin / 社区管理员
[init] 初始密码：xxxxxxxxxxxx（仅本次打印，请立即登录并修改密码）
```

> 想自己指定初始密码：先在 `.env` 里加一行 `INIT_ADMIN_PASSWORD="你的密码"`，再执行 `pnpm db:init`（执行完可以从 `.env` 里删掉这行）。

### ⚠️ 三条绝对不能执行的命令（会破坏数据）

| 命令 | 后果 |
| --- | --- |
| `pnpm db:seed` | 写入**整套演示数据**（演示用户、需求、活动、商城订单、审计日志…），只适合本地开发 |
| `pnpm db:reset` | **清空整个数据库**再重建，生产环境等于删库 |
| `pnpm db:init` 重复执行 | 会被脚本自动拒绝（不会写坏数据），但请不要用 `--force` 之类的方式绕过 |

**看到什么算成功**：`db:init` 打印了一串 `实体计数`，并且最后两行是超级管理员账号与初始密码。

**顺手检查一下数据库**：1Panel →「数据库 → PostgreSQL」→ 点 `joinyuu` → 「管理」→ 能看到一堆数据表（如 `User`、`CommunityEvent`、`AdminUser` 等）。

## 11. 第 9 步：让后端常驻运行

「常驻运行」= 关机重启后自己起来、崩了自己重拉。下面三种方式**选一种**即可：

- **都在面板里点着完成、喜欢 1Panel 的 UI** → [方案 A（运行环境 → Node.js）](#方案-a用-1panel运行环境--nodejs托管面板里点几下就行)。它是容器托管，需要按第 5 点改一下数据库地址；
- **想少一层容器网络的心智负担、追求最稳** → [方案 B（systemd）](#方案-b备选--systemd后端跑在服务器上最省心)，后端直接跑在服务器上，`.env` 里的 `127.0.0.1` 照旧可用；
- **已经习惯用 pm2** → [方案 C（pm2）](#方案-c备选--用-pm2)。

### 方案 A（用 1Panel「运行环境 → Node.js」托管，面板里点几下就行）

**动手前先理解一件事**：面板的「运行环境」本质是**容器**——它会把你的「项目目录」挂载进容器，在里面用你选的包管理器装依赖、按你填的启动命令跑进程，再做端口映射。由此带来两个后果：

- 容器里的 `127.0.0.1` 是**容器自己**，不是服务器 → 数据库/Redis 地址要改（见下面第 5 点）；
- 依赖建议**在服务器上用 pnpm 装好**（第 7 步已经做了）→ 面板里不要再让它装一遍。

#### 1）打开创建页

1Panel →「网站 → 运行环境 → Node.js」→「创建运行环境」（会从右侧滑出一个「创建」抽屉，底部有 **端口 / 环境变量 / 挂载 / 主机映射** 四个标签页）。

#### 2）逐字段填写

> 下表字段名与选项**按 1Panel v2.3.2 的实际界面核对过**（面板版本不同可能略有差异，含义一致）。

| 面板字段 | 填什么 | 为什么这么填 |
| --- | --- | --- |
| **名称** * | `joinyuu-api` | 面板里显示的名字，随意但不重名 |
| **应用** * | 左边选 `Node.js`；右边选 **20 或 22**（如 `22.22.2`、`20.20.2`） | 实测版本列表含 12/14/16/18/20/21/22/24/25；本项目要求 Node ≥ 20，**优先选 22 或 20 的 LTS**（默认高亮的是 25.9.0，属于最新非 LTS，能用但不必冒险） |
| **项目目录** * | `/opt/joinyuu`（**填仓库根，不要填 `/opt/joinyuu/apps/api`**） | pnpm 的 `node_modules` 是靠符号链接指向仓库根的 `node_modules/.pnpm` 的；只挂子目录会导致链接断掉，启动时报「找不到模块」。可用右侧文件夹按钮选目录，也可直接输入 |
| **启动命令** * | 打开右侧「**自定义启动命令**」开关，填 `pnpm --filter @joinyuu/api start` | 面板会在「项目目录」里执行这条命令，pnpm 会自己切到 `apps/api` 目录去跑 `node dist/main.js`，工作目录正确、能读到 `apps/api/.env`（详见下面第 4 点的三种写法）。**不打开这个开关**时，下拉是从项目目录的 `package.json` 解析脚本，而仓库根没有 `start` 脚本，所以必须自定义 |
| **容器名称** * | `joinyuu-api` | 后端容器的名字（1Panel「容器」列表里能看到） |
| **备注** | `聚屿社区后端 API` | 选填 |
| **包管理器** * | `npm`（保持默认） | 实测可选 `npm` / `yarn` / `pnpm`。既然下面关掉了自动安装，这一项不会被用到；若你决定让面板管依赖，则应选 `pnpm` 并打开「安装 node_modules」（见该行说明） |
| **安装 node_modules** | **关掉这个开关**（默认是开的） | 依赖已在第 7 步用 pnpm 装好；让容器再装一遍会用同一份挂载目录里的 `node_modules`，既可能与宿主机的结果互相覆盖，也可能因 Prisma 引擎与镜像 libc 不匹配而启动失败 |
| **镜像源** * | 保持「默认」，或按服务器网络选国内源 | 实测三选：`默认 [registry.npmjs.org]`、`淘宝 [registry.npmmirror.com]`、`腾讯 [mirrors.cloud.tencent.com/npm/]`；不自动安装依赖时无影响，若开启安装则国内服务器建议选淘宝 |

**底部四个标签页**（每行都要点「添加」才会出现一行，逐行填）：

| 标签页 | 填什么 | 说明 |
| --- | --- | --- |
| **端口** | 添加一行：协议 `tcp`、**应用端口** `7757`、**外部映射端口** `7757`；并把右侧「**端口外部访问**」开关**关掉** | 实测该开关**默认是开启的**＝端口绑到 `0.0.0.0`（对公网开放）。对外访问由 Nginx 的 `/api` 反代即可，不需要直接暴露 7757 |
| **环境变量** | 一般**留空**（后端读挂载目录里的 `apps/api/.env`） | 实测支持三种填法：① 行内添加 `名称` / `值`；② 点「**导入环境变量**」→ 弹窗里是一个 `KEY=value` 的文本框，可把 `.env` 内容整体粘进去；③ 都不用。**只有**当你采用的启动命令让工作目录变成了仓库根（见第 4 点第二种写法）时，才必须用①或②把配置注入进去 |
| **挂载** | 仅当 `.env` 里 `UPLOAD_DIR` 指向仓库外的目录时添加一行：**本机目录** `/data/joinyuu/uploads` → **容器目录** `/data/joinyuu/uploads`（权限保持「读写」） | 容器看不到宿主机目录；不挂载的话上传文件写进容器内部，**重启就丢**。`mobile-themes` 在项目目录内，随「项目目录」已挂载，无需另配 |
| **主机映射** | 用「容器名连数据库」时留空；用「宿主机端口连数据库」时添加一行：**主机名** `host.docker.internal`、**IP** `172.17.0.1` | 实测就是「主机名 + IP」两列，作用是往容器 `/etc/hosts` 写一行，让容器内能用该名字访问宿主机上的 5432/6379 |

#### 3）确认并观察状态

点「确认」，等列表里状态变成 **已启动（绿色）**：列表的列依次是「名称 / 项目目录 / 版本 / 外部映射端口 / 状态 / 日志 / 备注 / 时间 / 操作」，请顺带确认**「外部映射端口」列显示 7757**，再点该行的「日志」确认没有报错。

#### 4）启动命令的三种写法（选一种）

| 写法 | 怎么填 | 后果 |
| --- | --- | --- |
| **① 推荐** | 打开「自定义启动命令」，填 `pnpm --filter @joinyuu/api start` | 面板在项目目录（仓库根）执行它，pnpm 自己切到 `apps/api` 运行 `node dist/main.js` → 工作目录正确，`.env` 能读到，不需要在「环境变量」里额外配置 |
| ② 绝对路径直启 | 打开「自定义启动命令」，填 `node /opt/joinyuu/apps/api/dist/main.js` | 工作目录是仓库根 → **读不到 `apps/api/.env`**，必须在「环境变量」标签页用「导入环境变量」把 `.env` 内容粘进去 |
| ③ 用表单自带的下拉 | 不打开「自定义启动命令」，从下拉里选 | 下拉是从「项目目录」的 `package.json` 解析脚本；仓库根没有 `start` 脚本，所以本仓库用不了这项 |

> 面板自带的提示（打开「自定义启动命令」后可见）：「请填写完整的启动命令，例如：`npm run start`，**pm2 启动命令请换为 `pm2-runtime`**，否则会启动失败。」——如果你坚持用 pm2，请按这个提示改写命令。

#### 5）改数据库地址（关键一步，漏了会一直报 ECONNREFUSED）

后端跑在容器里时，`127.0.0.1` 指向容器自己。从下面两种改法里**选一种**：

**改法一（推荐）：用 1Panel 容器网络里的服务名**

1. 打开 1Panel「容器 → 容器」，找到 PostgreSQL、Redis 两个容器，记下它们的**名称**（就是第 4 步安装时你填的名称，例如 `postgresql`、`redis`）和它们所在的**网络**；
2. 确认 `joinyuu-api` 与它们在**同一个网络**（1Panel 安装的应用与运行环境默认在同一个网络里；若不在，在容器设置里把网络改成同一个）；
3. 编辑 `.env`（把 `postgresql`、`redis` 换成你看到的实际容器名）：

```ini
DATABASE_URL="postgresql://joinyuu:数据库密码@postgresql:5432/joinyuu?schema=public"
REDIS_URL="redis://:Redis密码@redis:6379/0"
```

4. **（容易漏）让服务器上的命令也能用同一个 `.env`**：容器名只在 Docker 网络里能解析，宿主机上跑 `pnpm db:migrate` 时解析不到，所以补两行 hosts 映射（1Panel 安装时已把 5432/6379 发布到宿主机）：

```bash
echo '127.0.0.1 postgresql' >> /etc/hosts
echo '127.0.0.1 redis'      >> /etc/hosts
```

5. 回到「运行环境 → Node.js」，点 `joinyuu-api` 的「重启」。

不确定容器名/网络时，可在终端执行：

```bash
docker ps --format '{{.Names}}\t{{.Networks}}\t{{.Ports}}'
```

**改法二（备选）：用「主机映射」走宿主机的端口**

1. 在运行环境的「主机映射」里加一条 `host.docker.internal:172.17.0.1`（`172.17.0.1` 是 Docker 默认网桥网关，可用 `ip addr show docker0` 核对）；
2. `.env` 改成：

```ini
DATABASE_URL="postgresql://joinyuu:数据库密码@host.docker.internal:5432/joinyuu?schema=public"
REDIS_URL="redis://:Redis密码@host.docker.internal:6379/0"
```

3. 同样补一行 hosts 映射，让宿主机上的 `pnpm db:migrate` 也能用这个 `.env`：

```bash
echo '127.0.0.1 host.docker.internal' >> /etc/hosts
```

4. 重启该运行环境。

> **两种改法都不顺利时，直接用方案 B（systemd）**：后端跑在服务器上，`.env` 里的 `127.0.0.1` 照旧可用，少一层容器网络的心智负担，也最稳。

> 该运行环境就是后端的「开关」：以后升级版本时，用列表里的「**重启**」按钮即可（见[后端升级手册](./backend-upgrade.md)）。

### 方案 B（备选 · systemd，后端跑在服务器上，最省心）

如果你不想处理容器网络/挂载这些事（或者方案 A 折腾不顺），直接用 Linux 自带的服务管理：后端就跑在服务器上，`.env` 里 `127.0.0.1` 照旧可用。终端里执行：

```bash
# 1) 创建服务文件
cat > /etc/systemd/system/joinyuu-api.service <<'EOF'
[Unit]
Description=Joinyuu Community API
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/joinyuu/apps/api
# 进程用户（建议与文件属主一致；先用 root 最简单）
User=root
Environment=NODE_ENV=production
# 后端自己会读取 apps/api/.env，无需在这里重复配置
ExecStart=/usr/bin/node dist/main.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# 2) 生效并启动
systemctl daemon-reload
systemctl enable joinyuu-api
systemctl start joinyuu-api

# 3) 查看状态（看到 active (running) 表示成功）
systemctl status joinyuu-api
```

以后常用：

```bash
systemctl restart joinyuu-api     # 重启（升级后用）
systemctl stop joinyuu-api        # 停止
journalctl -u joinyuu-api -n 200  # 看最近 200 行日志
```

### 方案 C（备选 · 用 pm2）

```bash
npm i -g pm2
cd /opt/joinyuu/apps/api && pm2 start dist/main.js --name joinyuu-api
pm2 save && pm2 startup   # 开机自启
```

### 三种方式都要做的验证

```bash
curl http://127.0.0.1:7757/api/health
```

**看到什么算成功**：返回一段 JSON（形如 `{"code":0,"data":{...}}`）。

**如果没反应**：

- 面板方案 → 在该运行环境的「日志」里看报错；
- systemd → `journalctl -u joinyuu-api -n 200`；
- 最常见的报错：
  1. `.env` 里密码写错（连不上数据库/Redis）；
  2. `NODE_ENV=production` 但 `JWT_SECRET` 没填（会直接启动失败）；
  3. `dist/main.js` 不存在（第 7 步构建没成功）；
  4. **（容器方案专属）连库报 `ECONNREFUSED 127.0.0.1:5432`** → 按方案 A 第 5 点把 `.env` 的主机名改成容器名或 `host.docker.internal`，然后重启；
  5. **（容器方案专属）报 `Cannot find module` 或 Prisma 引擎错误** → 「项目目录」没填仓库根，或「安装 node_modules」忘了关。

## 12. 第 10 步：构建管理端与移动端页面

**在哪里做**：1Panel 终端，项目根目录。

```bash
cd /opt/joinyuu

# 构建管理后台（产物 apps/admin/dist）
pnpm build:admin

# 构建移动端（产物 apps/client-mobile/dist）
pnpm build:client-mobile
```

**看到什么算成功**：两个命令都无红色 `Error`，且存在下面两个 `index.html`：

```bash
ls -l /opt/joinyuu/apps/admin/dist/index.html /opt/joinyuu/apps/client-mobile/dist/index.html
```

**建议把这两份产物移到固定目录**（后面 Nginx 就指向这里，升级时替换即可）：

```bash
mkdir -p /data/joinyuu/sites/admin /data/joinyuu/sites/mobile
cp -r /opt/joinyuu/apps/admin/dist/. /data/joinyuu/sites/admin/
cp -r /opt/joinyuu/apps/client-mobile/dist/. /data/joinyuu/sites/mobile/
# 给 Nginx 读文件的权限
chown -R root:root /data/joinyuu/sites
chmod -R 755 /data/joinyuu/sites
```

> 为什么要复制一份？因为下次重新构建会覆盖 `apps/*/dist`；而 Nginx 指向的目录保持不动，升级时你只需把新产物再复制进去（见[升级手册](./backend-upgrade.md)）。

## 13. 第 11 步：在 1Panel 创建两个网站

**在哪里做**：1Panel →「网站 → 网站」→ 右上角「创建网站」。

> 如果弹出提示说 OpenResty（Nginx）未安装，点「确认安装」装上即可。

### 13.1 创建管理后台网站

1. 创建网站 → 选择「**静态网站**」。
2. 填写：

| 字段 | 填什么 |
| --- | --- |
| 分组 | 保持默认（或新建 `joinyuu` 分组） |
| 主域名 | `admin.你的域名`（不要写 http://） |
| 代号 | `joinyuu-admin` |
| 启用 HTTPS | 先不勾（证书在第 13 步配置，避免卡住） |
| 备注 | 管理后台 |

3. 创建完成后：点这个网站 → 进入「网站目录 / 运行目录」设置 → 把目录指向 `/data/joinyuu/sites/admin`。
4. 用浏览器访问 `http://admin.你的域名`，**应能看到管理后台的登录页**（此时还没有数据接口，输入账号登录会失败，这是正常的，第 12 步配好反向代理就正常了）。

### 13.2 创建移动端网站

1. 创建网站 →「**静态网站**」，主域名填 `m.你的域名`，代号 `joinyuu-mobile`。
2. 网站目录指向 `/data/joinyuu/sites/mobile`。
3. 访问 `http://m.你的域名`，**应能看到移动端首页**。

> ⚠️ 移动端用的是「路径式」前端路由，**必须独占一个域名的最顶层**。不要把它放到 `admin.你的域名/m/` 这类子目录，否则刷新页面会 404。

### 13.3 补一条 SPA 兜底规则（移动端必做）

移动端刷新任意页面（如 `/me/profile`）时，Nginx 需要把请求交回 `index.html`，否则会 404。

1. 1Panel →「网站」→ 点移动端网站 →「网站配置」→ 找到「配置文件 / 源文」编辑入口。
2. 在 `server { ... }` 里确认存在下面这段（不存在就加上，注意保留原有内容不要删）：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

3. 保存后 Nginx 会自动重载。

## 14. 第 12 步：配置反向代理（让页面能调后端）

两个网站都要配。目的是：浏览器访问 `https://admin.你的域名/api/***` 时，由 Nginx 悄悄转发到本机的 `127.0.0.1:7757`。

### 14.1 添加代理

1. 1Panel →「网站」→ 点管理后台网站 →「反向代理」→「创建反向代理」。
2. 填写：

| 字段 | 填什么 |
| --- | --- |
| 名称 | `api` |
| 匹配规则 / 路径 | `/api`（有的版本写作 `/api/`，填 `/api` 即可） |
| 代理地址 | `http://127.0.0.1:7757` |
| 备注 | 后端接口 |

3. 保存。然后**对移动端网站重复一次同样的操作**（移动端也需要 `/api` 代理）。

### 14.2 提高上传体积上限（重要）

Nginx 默认只允许 1MB 的上传，而本系统默认允许 10MB（可在后台配置，最大 100MB）。不改这条，用户上传图片/合同会失败。

1. 1Panel →「网站」→ 点网站 →「网站配置」→ 编辑配置文件。
2. 在 `server { ... }` 段里加入一行（两个网站都加）：

```nginx
client_max_body_size 100m;
```

### 14.3 验证代理是否通了

浏览器直接访问下面的地址（把域名换掉）：

```
https://admin.你的域名/api/health
```

**看到什么算成功**：浏览器显示一段 JSON（`{"code":0,...}`）。

| 你看到的 | 说明 | 怎么办 |
| --- | --- | --- |
| 一段 JSON | 代理成功 | 继续下一步 |
| 404 页面 | 代理没生效或路径不匹配 | 检查第 14.1 步的匹配规则是否为 `/api` |
| 502 Bad Gateway | 代理通了，但后端没在跑 | 回到第 11 步确认后端状态与日志 |
| 一直转圈/超时 | 服务器防火墙或安全组没放行 443/80，或域名解析没生效 | 检查第 5 步与 DNS 解析 |

## 15. 第 13 步：配置 HTTPS 证书

**方式一：面板自动申请（推荐，免费）**

1. 1Panel →「网站 → 证书」→「申请证书」→ 填写你的域名（`admin.你的域名`、`m.你的域名`）→ 选择 ACME 账户（没有就按提示创建，邮箱随便填一个可用的）→ 提交。
2. 申请成功后，回到「网站」→ 点网站 →「网站配置」→ 勾选「启用 HTTPS」→ 选择刚签发的证书 → 保存。
3. 建议同时打开「HTTP 自动跳转到 HTTPS」。

**方式二：上传已有证书**

1. 1Panel →「网站 → 证书」→「上传证书」→ 把云厂商下载的 `.crt/.pem`（证书内容）与 `.key`（私钥）分别粘贴进去 → 保存。
2. 再按上面的方式在网站里启用 HTTPS。

**看到什么算成功**：浏览器地址栏出现小锁图标，访问 `https://admin.你的域名` 与 `https://m.你的域名` 都不再提示「不安全」。

> 证书一般 90 天到期。面板签发的证书会自动续签；自己上传的证书到期前记得换新。

## 16. 第 14 步：首次登录与业务初始化

### 16.1 登录并改密码

1. 打开 `https://admin.你的域名`。
2. 用户名 `admin`，密码用第 10 步打印出来的初始密码（要输入页面上的图形验证码）。
3. 登录后立刻：右上角头像 →「修改密码」→ 换成你自己的强密码。

### 16.2 导入许可证（⚠️ 必做，否则系统只读）

系统的所有「写入类」操作都受许可证控制：没有导入许可证时，只能查看/导出，不能新增活动、审核申请、发布需求等。

1. 在管理后台进入「系统管理 → 系统配置 → 基础设置 → 许可证管理」。
2. 点「生成申请文件」，下载 `license-request-xxxx.json`，发给供应商签发。
3. 收到 `.license` 文件后，在同一页面点「导入许可证」上传。
4. 状态显示为**有效**即可（到期时间按北京时间展示）。

> 详细规则见[许可证管理](./license-management.md)。

### 16.3 按需完成的初始化配置

| 位置 | 做什么 |
| --- | --- |
| 系统管理 → 系统配置 → 基础设置 | 站点名称、Slogan、各业务开关（注册/商城/需求/预约/首页轮播）；若要启用 MinIO：打开「对象存储」开关，填 Endpoint `127.0.0.1`、端口 `9000`、Bucket（如 `joinyuu`）、不使用 TLS（密钥已在 `.env` 注入，页面只显示「已配置」） |
| 系统管理 → 系统配置 → 通知渠道配置 | 需要真实发短信/邮件时：先在服务器 `.env` 里注入渠道凭据（见下方说明），再把渠道的凭据来源设为「环境变量」并点「测试发送」验证 |
| 系统管理 → 系统配置 → 移动端主题 | 上传/切换客户主题包（可选） |
| 系统管理 → 角色与账号 | 创建运营、审核等子账号并分配角色（**不要**再使用演示密码 `admin123`） |
| 系统管理 → 素材库 | 查看与管理已上传的图片、合同附件 |
| 系统管理 → 日志与审计 | 查看登录日志与操作审计 |
| 规则管理 | 积分规则、经验规则、等级梯度、发布限制（新库默认发布不限制，可按运营策略收紧） |

**短信/邮件凭据示例**（写进 `/opt/joinyuu/apps/api/.env` 后重启后端）：

```ini
ALIYUN_SMS_ACCESS_KEY_ID="你的 AccessKeyId"
ALIYUN_SMS_ACCESS_KEY_SECRET="你的 AccessKeySecret"
SMTP_USER="你的邮箱账号"
SMTP_PASSWORD="邮箱授权码"
```

> `.env` 里变量名要与后台渠道里登记的变量名一致（种子渠道默认已登记阿里云短信与 SMTP 的这两个名字）。改完 `.env` 必须**重启后端**才生效。

## 18. 日常运维：备份、看日志、重启

### 18.1 备份（强烈建议设成每天自动执行）

**要备份三样东西**：数据库、上传的文件、代码版本号。

**用 1Panel 做数据库定时备份**：

1. 1Panel →「数据库 → PostgreSQL」→ 点 `joinyuu` →「备份」。这里可以点一次「立即备份」验证可用。
2. 1Panel →「计划任务」→「创建任务」→ 类型选「备份数据库」→ 目标选 `joinyuu` → 周期选「每天」→ 时间选凌晨 3 点 → 保留份数 7 → 保存。
3. 备份文件默认落在 1Panel 的备份目录，可在「计划任务 → 备份」里查看与下载。

**手工备份命令**（等效，随时可用）：

```bash
# 数据库导出到文件（把密码换成你的）
PGPASSWORD='你的数据库密码' pg_dump -h 127.0.0.1 -U joinyuu -d joinyuu -Fc -f /data/joinyuu/backup/db-$(date +%F).dump

# 上传文件与主题包打包
tar -czf /data/joinyuu/backup/uploads-$(date +%F).tar.gz -C /data/joinyuu uploads
tar -czf /data/joinyuu/backup/themes-$(date +%F).tar.gz  -C /opt/joinyuu/apps/api mobile-themes 2>/dev/null || true

# 记录当前代码版本
cd /opt/joinyuu && git rev-parse HEAD >> /data/joinyuu/backup/versions.log
```

### 18.2 看日志

| 要看什么 | 在哪里看 |
| --- | --- |
| 后端运行日志 | 方案 A：1Panel「运行环境 → Node.js」→ 该环境的「日志」；方案 B：`journalctl -u joinyuu-api -n 200` |
| Web 访问日志 | 1Panel「网站」→ 点网站 →「日志」 |
| 数据库日志 | 1Panel「数据库 → PostgreSQL」→ 该库的「日志」（或应用商店 → 已安装 → PostgreSQL → 日志） |
| 业务审计日志 | 管理后台「系统管理 → 日志与审计」 |

### 18.3 重启顺序（出问题时按这个顺序操作）

```bash
systemctl restart joinyuu-api     # 或面板运行环境的「重启」按钮
```

只要**后端重启**即可（前端是静态文件，不用管）。只有数据库/Redis 也异常时，才用 1Panel「应用商店 → 已安装」里的「重启」按钮。

## 19. 常见问题排查（症状 → 原因 → 解决）

| 症状 | 最可能的原因 | 解决 |
| --- | --- | --- |
| 网页打开是空白/一直转圈 | 前端产物没放对目录，或网站目录没指向 `dist` | 检查第 13 步的「网站目录」设置 |
| 页面能打开，但所有列表转圈后报错 | `/api` 反向代理没配好 | 按第 14.1 步重配，并用 `/api/health` 自测 |
| 接口 502 | 后端没在运行 | 看第 11 步的状态与日志；90% 是 `.env` 写错或 `JWT_SECRET` 缺失 |
| 接口 404（页面本身正常） | 代理的匹配规则不是 `/api` | 改成 `/api` 后保存 |
| 上传图片/合同失败 | Nginx 上传体积限制 | 按第 14.2 步加 `client_max_body_size 100m;` |
| 移动端刷新某页变 404 | 缺 SPA 兜底规则 | 按第 13.3 步加 `try_files $uri $uri/ /index.html;` |
| 登录提示「验证码错误或已过期」反复出现 | 反向代理没传真实 IP，或访问的不是配置的域名 | 确认 `TRUST_PROXY=1`、用域名访问（不要用 IP） |
| 列表里的时间差 8 小时 | 服务器时区不是东八区 | 在 `.env` 保留 `TZ="Asia/Shanghai"`，并重启后端；服务器系统时区可用 `timedatectl set-timezone Asia/Shanghai` |
| 日志里的访问 IP 都是 `127.0.0.1` | 代理信任设置或 Nginx 头缺失 | 保持 `TRUST_PROXY=1`，并确认 1Panel 反向代理默认转发了 `X-Forwarded-For` |
| 提示「密码已过期，请先修改密码」 | 后台开启了「密码过期强制改密」 | 用该账号在登录页走「忘记密码」，或让超管关闭该开关 |
| 所有写入操作都被拒绝，只读 | 许可证未导入/已过期 | 按第 16.2 节导入许可证 |
| `pnpm install` 报 `ENOSPC` | 磁盘满 | 1Panel「系统 → 监控」看磁盘，清理 `/var/lib/docker` 或旧备份 |
| `pnpm build:*` 被杀进程（Killed） | 内存不足 | 按第 9 步临时加交换分区 |
| 数据库连不上（ECONNREFUSED 5432） | 应用商店里 PostgreSQL 没启动，或端口改了没同步 `.env` | 1Panel「应用商店 → 已安装」确认状态；改端口后同步 `.env` 并重启后端 |
| Redis 报 `NOAUTH Authentication required` | `.env` 里的 Redis 密码漏写或格式错 | 写成 `redis://:密码@127.0.0.1:6379/0` |
| 后端启动即退出，日志写 `JWT_SECRET 未配置` | `NODE_ENV=production` 但没填 `JWT_SECRET` | 按第 6 步生成并填入后重启 |
| **（用面板运行环境时）**日志报 `ECONNREFUSED 127.0.0.1:5432` 或 `...6379` | 容器里的 `127.0.0.1` 是容器自己，不是服务器 | 按[第 9 步方案 A](#11-第-9-步让后端常驻运行) 第 5 点，把 `.env` 的主机名改成数据库容器名或 `host.docker.internal`，再在面板上重启运行环境 |
| **（用面板运行环境时）**日志报 `Cannot find module '...'` 或 Prisma 引擎加载失败 | 「项目目录」填成了 `apps/api`（pnpm 符号链接断链），或「安装 node_modules」没关 | 「项目目录」改为 `/opt/joinyuu`，「安装 node_modules」关闭，重启运行环境 |
| **（用面板运行环境时）**运行环境状态在「启动中 → 已停止」之间反复 | 启动命令写错，或工作目录导致 `.env` 读不到、进程立刻退出 | 按[方案 A 第 4 点](#方案-a用-1panel运行环境--nodejs托管面板里点几下就行)改为 `pnpm --filter @joinyuu/api start`；若只能用绝对路径直启，就在「环境变量 → 导入环境变量」里把 `.env` 内容整体粘进去，并在「日志」里核对报错 |
| **（用面板运行环境时）**上传的图片/合同在重启后消失 | `UPLOAD_DIR` 指向仓库外的目录，但没在「挂载」里配 | 在运行环境的「挂载」里加：宿主机 `/data/joinyuu/uploads` → 容器 `/data/joinyuu/uploads`，重启 |

## 20. 附录

### 20.1 端口一览

| 端口 | 服务 | 对外 | 说明 |
| --- | --- | --- | --- |
| 80 | Nginx(OpenResty) | ✅ | HTTP，用于证书签发与跳转 |
| 443 | Nginx(OpenResty) | ✅ | HTTPS 正式访问 |
| 面板端口 | 1Panel | ✅（可限 IP） | 管理面板 |
| 7757 | 后端 API | ❌ | 仅本机 Nginx 访问 |
| 5432 | PostgreSQL | ❌ | 仅本机后端访问 |
| 6379 | Redis | ❌ | 仅本机后端访问 |
| 9000 / 9001 | MinIO API / 控制台 | ❌ | 需要时用 SSH 隧道临时查看 |

### 20.2 关键目录一览

| 路径 | 内容 | 升级时 |
| --- | --- | --- |
| `/opt/joinyuu` | 项目代码 | 需要更新 |
| `/opt/joinyuu/apps/api/dist` | 后端构建产物 | 重新构建 |
| `/data/joinyuu/sites/admin`、`/data/joinyuu/sites/mobile` | 两个前端产物（Nginx 指向这里） | 替换内容 |
| `/data/joinyuu/uploads`（或 `apps/api/uploads`） | 用户上传的图片/合同 | ⚠️ **必须保留，不要删** |
| `/opt/joinyuu/apps/api/mobile-themes` | 已安装的移动端主题包 | ⚠️ **必须保留，不要删** |
| `/data/joinyuu/backup` | 备份文件 | 保留 |

### 20.3 环境变量速查（详见 `apps/api/.env.example`）

| 变量 | 必填 | 作用 |
| --- | --- | --- |
| `NODE_ENV` | ✅ | 固定 `production` |
| `DATABASE_URL` | ✅ | PostgreSQL 连接串 |
| `REDIS_URL` | ✅ | Redis 连接串（密码前有冒号） |
| `JWT_SECRET` | ✅ | 登录凭证密钥（`openssl rand -hex 32`） |
| `INIT_ADMIN_PASSWORD` | 否 | 仅 `db:init` 使用，指定超管初始密码 |
| `PORT` | 否 | 后端端口，默认 7757 |
| `TZ` | 否 | 固定 `Asia/Shanghai` |
| `TRUST_PROXY` | 否 | 反向代理层数，走 Nginx 填 1 |
| `CORS_ORIGINS` | 否 | 同源部署**不用配**；只有跨域访问才需要 |
| `UPLOAD_DIR` | 否 | 上传文件目录 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 否 | MinIO 密钥（Endpoint/Bucket 在后台配置） |
| `ALIYUN_SMS_*` / `TENCENT_SMS_*` / `SMTP_*` | 否 | 短信/邮件渠道凭据 |
| `AUTH_REVOCATION_FAIL_OPEN` | 否 | 仅在 Redis 故障排障时临时设为 1 |

### 20.4 命令速查

| 目的 | 命令（在 `/opt/joinyuu` 下执行） |
| --- | --- |
| 应用数据库迁移 | `pnpm db:migrate` |
| 写入基础配置（仅首次） | `pnpm db:init` |
| 构建后端 | `pnpm build:api` |
| 构建管理端 / 移动端 | `pnpm build:admin` / `pnpm build:client-mobile` |
| 重启后端（systemd 方案） | `systemctl restart joinyuu-api` |
| 健康检查 | `curl http://127.0.0.1:7757/api/health` |

### 20.5 一句话总结部署流程

> 装面板 → 装 PostgreSQL 与 Redis → 放行 80/443 → 放代码 → 写 `.env` → `pnpm install` → `pnpm build:api` → `pnpm db:migrate` → `pnpm db:init` → 后端跑起来（用面板运行环境时记得按方案 A 第 5 点改数据库地址）→ 构建两个前端 → 建两个静态网站 → 各加一条 `/api` 反向代理 → 配 HTTPS → 登录改密码 + 导入许可证。

升级已有部署请看[后端升级手册](./backend-upgrade.md)。
